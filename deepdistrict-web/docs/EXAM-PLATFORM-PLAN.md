# แผนออกแบบ: DeepDistrict Examination & Learning Platform

ฉบับร่าง 30 ต.ค. 2569 · ต่อยอดจากระบบปัจจุบัน (เว็บไซต์ + ระบบหลังบ้าน + พอร์ทัลผู้เรียน)

## 1. เป้าหมาย

1. **คลังข้อสอบ (Item Bank)** ในฐานข้อมูล ข้อสอบมีระดับความยากและหมวดเนื้อหาครบ ทั้งที่ AI ช่วยร่างและครูเขียนเอง ทุกข้อต้องผ่านการตรวจก่อนใช้
2. **ชุดสอบ Mock ครบทุกพาร์ต** สุ่มจากคลังตาม "พิมพ์เขียว" (blueprint) แยกตามหมวดและระดับความยาก
3. **SAT แบบปรับระดับ (Multistage Adaptive Testing, MST)**
   - ผลโมดูล 1 กำหนดว่าโมดูล 2 จะยากหรือง่าย
   - ถ้าได้โมดูล 2 แบบง่าย คะแนนสูงสุดที่ทำได้จะถูกจำกัด (score ceiling)
   - College Board ไม่เปิดเผยเกณฑ์ตัดและเพดานคะแนน ตัวเลขที่พบเป็นการประเมินจากภายนอก เช่น ประมาณ 590–700 ต่อพาร์ต
4. **ห้องเรียนสด (Live class)** หน้าจอครูและนักเรียนแสดงข้อสอบข้อเดียวกันพร้อมกัน ครูเห็นเฉลยละเอียด นักเรียนไม่เห็นจนกว่าครูจะเปิด
5. **โหมดฝึกเอง (Practice)** นักเรียนทำเอง ได้เฉลยแบบสั้น
6. **หลายวิชาและหลายระดับ**
   - แกนหลัก: SAT (Math, Reading & Writing) และ IELTS (Listening, Reading, Writing, Speaking)
   - ภาษาอังกฤษ: ป.4–ป.6 → ม.1 · ม.1–ม.3 → ม.4 · ม.4–ม.6 → A-Level (TCAS)
   - เพิ่มวิชาอื่นได้ภายหลัง โดยไม่ต้องแก้โค้ดหลัก
7. **สร้าง PDF ได้ทุกเวลา**
   - มีโลโก้ วิธีใช้ ขอบเขตทางกฎหมาย และลิขสิทธิ์
   - ทุกครั้งที่สร้าง จะสุ่มชุดใหม่ ระบุวัน-เวลา ผู้สร้าง และผู้ใช้ที่ล็อกอิน
   - บันทึกลงฐานข้อมูลทุกครั้ง และตรวจสอบย้อนกลับได้
8. **ขยายได้** เพิ่มโมดูลอื่นในอนาคตโดยไม่รื้อของเดิม

## 2. หลักการออกแบบ

| หลักการ | ทำอย่างไร |
| --- | --- |
| **เฉลยไม่ออกจากเซิร์ฟเวอร์ถ้าไม่มีสิทธิ์** | API ฝั่งนักเรียนไม่ส่งคำตอบหรือคำอธิบายเลย ไม่ใช่แค่ซ่อนบนหน้าจอ ครูได้ข้อมูลผ่าน API ของครูเท่านั้น |
| **ข้อสอบเป็นข้อมูล ไม่ใช่โค้ด** | วิชา หมวด พิมพ์เขียว วิธีคิดคะแนน และการปรับระดับ เก็บเป็นข้อมูล เพิ่มวิชาใหม่ = เพิ่มข้อมูล |
| **ทุกข้อมีเวอร์ชัน** | แก้ข้อสอบแล้วได้เวอร์ชันใหม่ ชุดสอบและผลสอบเดิมยังอ้างเวอร์ชันเดิม จึงย้อนดูได้เสมอ |
| **AI ร่าง คนอนุมัติ** | ข้อสอบจาก AI เริ่มที่สถานะ "ร่าง" ต้องมีครูตรวจก่อนถึงมือนักเรียน |
| **ทุกการกระทำสำคัญมีบันทึก** | สร้าง/แก้/อนุมัติข้อสอบ, สร้าง PDF, ล็อกอิน, เปิดห้องเรียนสด, เปิดเฉลย |
| **ใช้ของเดิมให้มากที่สุด** | ใช้บัญชีผู้ใช้ สิทธิ์ (admin / teacher / student / parent) การลงทะเบียน โลโก้ ตราประทับ และระบบแจ้งเตือนเดิม |
| **ย้ายระบบได้ในอนาคต** | ใช้ SQL มาตรฐาน, ID แบบสุ่มที่ไม่ซ้ำ, ไฟล์สื่อเก็บนอกฐานข้อมูล ย้ายไป PostgreSQL หรือ Django ได้โดยไม่เปลี่ยนแบบข้อมูล |

## 3. โครงสร้างโมดูล (ขยายได้)

ตอนนี้ `server/app.py` ใช้ if-path ต่อกันยาว ก่อนเริ่มโมดูลข้อสอบควรปรับเป็นระบบลงทะเบียนโมดูล:

```
server/
  app.py            แกนกลาง: HTTP, session, สิทธิ์, audit, static
  core/             (ย้ายจาก app.py) db, auth, audit, migrations, router
  modules/
    notify/         (มีแล้ว)  แจ้งเตือน
    popups/         (มีแล้ว)  ป๊อปอัป
    exams/          ใหม่: คลังข้อสอบ, พิมพ์เขียว, ชุดสอบ, ผลสอบ, คิดคะแนน
    live/           ใหม่: ห้องเรียนสด (sync ผ่าน polling)
    exports/        ใหม่: สร้าง PDF + บันทึก + ตรวจสอบ
    ai/             ใหม่: ร่างข้อสอบด้วย AI + ตรวจอัตโนมัติ (งานเบื้องหลัง)
```

- **แต่ละโมดูล** มี `migrations` (ตาราง), `routes` (`/api/<module>/...`) และ `permissions`
- **แกนกลาง** ค้นหาโมดูลเองตอนเริ่มระบบ เพิ่มโมดูลใหม่จึงไม่ต้องแก้แกน
- **Migrations:** มีตาราง `schema_versions` ที่บันทึกว่าแต่ละโมดูลอัปเดตถึงเวอร์ชันไหน เปลี่ยนตารางทีละขั้นได้อย่างปลอดภัย

## 4. แบบข้อมูล (ตารางหลัก)

| ตาราง | เก็บอะไร |
| --- | --- |
| `subjects` | วิชา/ข้อสอบ เช่น `SAT_M`, `SAT_RW`, `IELTS_L/R/W/S`, `ENG_P6_M1`, `ENG_M3_M4`, `ENG_ALEVEL` |
| `domains` | หมวดเนื้อหาแบบลำดับชั้น เช่น SAT Math → Algebra → Linear equations · SAT RW → Craft & Structure → Words in context |
| `passages` | บทอ่าน บทฟัง (สคริปต์ + ไฟล์เสียง) กราฟ หรือตารางที่หลายข้อใช้ร่วมกัน |
| `items` | ข้อสอบ: วิชา หมวด ทักษะ ประเภท ระดับความยาก 1–5 สถานะ ผู้สร้าง แหล่งที่มา (AI/ครู) |
| `item_versions` | เนื้อหาแต่ละเวอร์ชัน: โจทย์ ตัวเลือก คำตอบ เฉลยสั้น (นักเรียน) เฉลยละเอียด (ครู) สื่อ เกณฑ์ให้คะแนน (Writing/Speaking) |
| `item_stats` | สถิติจริง: จำนวนครั้งที่ใช้ อัตราตอบถูก ค่าความยากเชิงสถิติ ค่าอำนาจจำแนก เวลาเฉลี่ย |
| `blueprints` | พิมพ์เขียว: ส่วน/โมดูล เวลา จำนวนข้อต่อหมวด×ระดับ กฎการปรับระดับ วิธีคิดคะแนน |
| `forms` | ชุดสอบที่สุ่มแล้ว: ตัวเลขตั้งต้นการสุ่ม (seed), รายการข้อ+เวอร์ชันต่อโมดูล, จุดประสงค์ (ฝึก / mock / สด / PDF) |
| `attempts` | การสอบแต่ละครั้ง: ผู้สอบ ชุดสอบ โหมด เวลาเริ่ม-จบ เส้นทางโมดูล คะแนนดิบ คะแนนประมาณ |
| `responses` | คำตอบรายข้อ: คำตอบ ถูก/ผิด เวลาที่ใช้ การทำเครื่องหมายไว้ |
| `live_sessions` / `live_participants` | ห้องเรียนสด: ครู ชั้นเรียน ชุดสอบ ข้อปัจจุบัน สถานะ (เปิด / ล็อกคำตอบ / เปิดเฉลย) ผู้เข้าร่วม |
| `exports` | การสร้าง PDF ทุกครั้ง: ชนิด ชุดสอบ ผู้สร้าง ผู้รับ เวลา รหัสตรวจสอบ ค่า hash ของเนื้อหา |
| `ai_jobs` | งานร่างข้อสอบด้วย AI: คำขอ พิมพ์เขียว สถานะ จำนวนผลลัพธ์ ค่าใช้จ่าย ผลตรวจอัตโนมัติ |
| `audit` (มีแล้ว ขยาย) | เพิ่มคอลัมน์ `module`, `action`, `object_id` และเริ่มบันทึกการล็อกอินและออกจากระบบ |

**สถานะของข้อสอบ:** `draft` (ร่าง) → `review` (รอตรวจ) → `approved` (ใช้ได้) → `retired` (เลิกใช้)
- ทุกการเปลี่ยนสถานะลงบันทึก
- ข้อที่ถูกใช้ในผลสอบแล้วห้ามลบ ให้เลิกใช้ (retire) แทน

**ระดับความยาก:**
- เริ่มจากค่าที่ AI หรือครูประเมิน (1–5)
- เมื่อมีคนทำครบประมาณ 30–50 ครั้ง ระบบคำนวณค่าความยากจากข้อมูลจริง และแจ้งครูเมื่อค่าประเมินกับค่าจริงต่างกันมาก
- เมื่อข้อมูลพอ อัปเกรดเป็นโมเดล IRT (Rasch) เพื่อคิดคะแนนแบบปรับระดับได้แม่นขึ้น

## 5. การสุ่มชุดสอบ (สุ่มแบบชั้นภูมิ)

ตัวอย่างพิมพ์เขียว SAT Math โมดูล 1:

```
Algebra            8 ข้อ : ง่าย 3 · กลาง 3 · ยาก 2
Advanced Math      7 ข้อ : ง่าย 2 · กลาง 3 · ยาก 2
Problem-Solving    4 ข้อ : ง่าย 1 · กลาง 2 · ยาก 1
Geometry & Trig    3 ข้อ : ง่าย 1 · กลาง 1 · ยาก 1
เวลา 35 นาที · ไม่ใช้ข้อที่ผู้เรียนเคยเห็นใน 60 วันล่าสุด
```

- **วิธีสุ่ม:** สุ่มทีละช่อง (หมวด × ระดับ) จากข้อที่สถานะ `approved`
- **ลดข้อซ้ำ:** ข้อที่ผู้เรียนเคยเห็นแล้ว และข้อที่ถูกใช้บ่อย จะได้น้ำหนักน้อยลง
- **บทอ่านที่มีหลายข้อ:** ดึงข้อที่ใช้บทอ่านเดียวกันมาเป็นกลุ่ม
- **seed ถูกบันทึกไว้:** สร้างชุดเดิมซ้ำได้เสมอ ใช้ตรวจสอบย้อนหลัง และสร้าง PDF ที่ตรงกับชุดสอบออนไลน์
- **คลังไม่พอ:** ระบบแจ้งให้ครูทราบ ไม่สร้างชุดที่ไม่ครบเงียบ ๆ

## 6. SAT แบบปรับระดับ และการคิดคะแนน

```
โมดูล 1 (ระดับผสม) ──► ได้ถูก ≥ เกณฑ์? ──ใช่──► โมดูล 2 ยาก  (คะแนนเต็ม 800)
                                  └─ไม่──► โมดูล 2 ง่าย  (มีเพดานคะแนน)
```

- **ตั้งค่าได้ในพิมพ์เขียว:** เกณฑ์แยกเส้นทาง เพดานคะแนน และตารางแปลงคะแนน ปรับได้โดยไม่ต้องแก้โค้ด
- **ผลที่แสดง:** "คะแนนประมาณ" เป็นช่วง เช่น 650–690 พร้อมข้อความว่า *ไม่ใช่คะแนนจริงของ College Board*
- **ระยะแรก:** แปลงคะแนนด้วยตาราง ตามจำนวนข้อถูกและเส้นทางโมดูล
- **ระยะต่อไป:** ใช้ IRT (Rasch) จากสถิติข้อสอบของเราเอง
- **IELTS:**
  - Listening/Reading แปลงคะแนนดิบ /40 เป็น Band ตามตารางโดยประมาณ
  - Writing/Speaking ให้คะแนนตามเกณฑ์ 4 ด้านที่ IELTS เผยแพร่ AI ช่วยร่างคะแนนและคำแนะนำ แต่ครูเป็นผู้ยืนยัน
- **ข้อสอบภาษาอังกฤษไทย** (ป.6→ม.1, ม.3→ม.4, A-Level): คิดคะแนนแบบตรง ๆ ตามจำนวนข้อถูกและสัดส่วนหมวด พร้อมรายงานจุดอ่อนรายหมวด

## 7. โหมดการใช้งาน

| โหมด | ใคร | สิ่งที่เห็น |
| --- | --- | --- |
| **ห้องเรียนสด** | ครูควบคุม นักเรียนทำตาม | ข้อเดียวกันพร้อมกัน · ครูเห็นเฉลยละเอียด สถิติคำตอบของห้อง และใครตอบแล้ว · นักเรียนเห็นเฉพาะโจทย์ จนกว่าครูกด "เปิดเฉลย" ซึ่งจะเห็นแค่ถูก/ผิดและเฉลยสั้น |
| **ฝึกเอง** | นักเรียน | สุ่มชุดตามหมวดหรือระดับที่เลือก · รู้ผลทันทีพร้อมเฉลยสั้น · ไม่มีเฉลยละเอียดของครู |
| **Mock เต็มรูปแบบ** | นักเรียน (ครูมอบหมาย) | จับเวลาตามจริง ปรับระดับแบบ SAT · เห็นผลหลังส่ง พร้อมคะแนนประมาณและจุดอ่อนรายหมวด |
| **มอบหมายงาน** | ครู → นักเรียน | ชุดที่ครูเลือกหรือสุ่ม พร้อมกำหนดส่ง ผลส่งเข้าพอร์ทัลผู้ปกครองอัตโนมัติ |

**การซิงก์ห้องเรียนสด**
- ใช้ **polling** ให้นักเรียนถามสถานะทุก 1–2 วินาที ผ่าน endpoint ที่เบามาก ซึ่งตอบ "ไม่เปลี่ยน" ได้ทันที
- ทำงานบน PythonAnywhere (WSGI) ได้เลย และพอสำหรับห้องเรียนขนาดเล็กถึงกลาง
- ถ้าวันหน้ามีหลายห้องพร้อมกันจำนวนมาก ค่อยเปลี่ยนเป็น WebSocket โดยไม่เปลี่ยนรูปแบบข้อมูล

## 8. AI ช่วยร่างข้อสอบ (ควบคุมคุณภาพ)

1. **ครูสั่งงาน:** เลือกวิชา หมวด ระดับ จำนวน และตัวอย่างแนวข้อสอบ (ที่เราเขียนเอง)
2. **AI ร่าง:** เรียกผ่าน API ฝั่งเซิร์ฟเวอร์ ได้ข้อมูลตามโครงสร้างที่กำหนด คือ โจทย์ ตัวเลือก คำตอบ เฉลยสั้น เฉลยละเอียด และระดับที่ประเมิน
3. **ตรวจอัตโนมัติ:**
   - ข้อมูลครบตามโครงสร้างหรือไม่
   - ให้ AI อีกรอบแก้โจทย์เองโดยไม่เห็นเฉลย แล้วเทียบคำตอบ
   - ตรวจข้อที่คล้ายข้อเดิมในคลัง
   - ตรวจความยาวและระดับภาษา
   - ห้ามคัดลอกข้อสอบจริงหรือข้อความจากหนังสือที่มีลิขสิทธิ์
4. **ครูตรวจและอนุมัติ:** ข้อที่ผ่านเข้าสถานะ "รอตรวจ" ครูแก้ไขแล้วอนุมัติ ระบบบันทึกผู้ร่าง ผู้ตรวจ และเวลา
5. **ข้อมูลประกอบ:** เก็บข้อมูลการสร้างทุกข้อ (ผู้ให้บริการ เวอร์ชันพรอมต์ ค่าใช้จ่าย) ไว้ตรวจสอบคุณภาพ

**บทฟัง IELTS:** AI ร่างสคริปต์ แล้วแปลงเป็นเสียงด้วยบริการ text-to-speech หรืออัดเสียงเอง ไฟล์เสียงเก็บนอกฐานข้อมูล

## 9. PDF + บันทึก + ลิขสิทธิ์

**ชนิดของ PDF**

| ชนิด | ใครสร้างได้ | เนื้อหา |

## 12. ข้อควรตัดสินใจก่อนเริ่ม

1. **โฮสติ้ง:**
   - ต้องเรียก AI API และส่งอีเมล/LINE จึงต้องใช้ PythonAnywhere แพ็กเกจ Developer (บัญชีฟรีออกอินเทอร์เน็ตได้จำกัด)
   - งาน AI ที่ใช้เวลานานควรรันเป็นงานเบื้องหลังหรือรันตามเวลา ไม่ใช่ระหว่างที่หน้าเว็บรอ
2. **ฐานข้อมูล:**
   - SQLite (WAL) พอสำหรับระยะ 0–4 และห้องเรียนขนาดเล็กถึงกลาง
   - ถ้าผู้ใช้พร้อมกันจำนวนมาก ค่อยย้ายไป PostgreSQL แบบข้อมูลที่ออกแบบไว้รองรับแล้ว
3. **แพลตฟอร์มโค้ด:**
   - ต่อยอดระบบปัจจุบัน (WSGI) ทำได้ทันทีและใช้บัญชีผู้ใช้เดิม
   - หากต้องการ Django ควรตัดสินใจก่อนระยะ 1 เพราะแบบข้อมูลข้างบนใช้ได้กับทั้งสองทาง
4. **ลิขสิทธิ์:** ห้ามนำข้อสอบจริงหรือข้อความจากหนังสือเตรียมสอบที่มีลิขสิทธิ์เข้าคลัง ใช้ได้เฉพาะข้อที่เราเขียนเองหรือ AI ร่างแล้วครูตรวจ ข้อความทางกฎหมายควรให้ทนายตรวจ
5. **PDPA:** บันทึกการล็อกอินและการสร้างเอกสารเป็นข้อมูลส่วนบุคคล ต้องระบุวัตถุประสงค์และระยะเวลาเก็บในนโยบายความเป็นส่วนตัว (เสนอ 3 ปี)
