# คณิตศาสตร์ของมือ — สมการทั้งหมดใน `js/geometry.js`
*Hand mathematics — every equation used in `js/geometry.js`, ready for Chapter 3 (บทที่ 3 วิธีดำเนินการ)*

MediaPipe Hand Landmarker ให้จุด 21 จุดต่อมือ แต่ละจุดมีค่า **x, y, z**:

- x = ตำแหน่งแนวนอน ÷ ความกว้างภาพ (0–1), y = ตำแหน่งแนวตั้ง ÷ ความสูงภาพ (0–1)
- z = ความลึกเทียบกับข้อมือ ใช้สเกลเดียวกับ x (ติดลบ = ใกล้กล้องกว่าข้อมือ)

หมายเลขจุดสำคัญ: 0 ข้อมือ · 4 ปลายนิ้วโป้ง · 8 ปลายนิ้วชี้ · 12 ปลายนิ้วกลาง · 16 ปลายนิ้วนาง · 20 ปลายนิ้วก้อย · 5, 9, 13, 17 ข้อโคนนิ้ว (knuckle) ของนิ้วชี้ กลาง นาง ก้อย

ขั้นตอนนี้เรียกว่า **feature engineering**: เปลี่ยนตัวเลขดิบให้เป็นตัวเลขที่มีความหมาย ถ้าตัวเลขที่ป้อนให้ AI ยังขึ้นกับระยะห่างจากกล้อง AI ก็จะเรียนรู้ผิดตั้งแต่ต้น

## 0. แก้สัดส่วนภาพก่อนคำนวณ — `squarePoints(pts, aspect)`

$$x' = x \cdot \frac{W}{H}, \qquad y' = y, \qquad z' = z \cdot \frac{W}{H}$$

**ทำไม:** x หารด้วยความกว้าง แต่ y หารด้วยความสูง บนภาพ 16:9 ระยะแนวนอน 0.1 ยาวกว่าระยะแนวตั้ง 0.1 ถึง 1.78 เท่า
ถ้าไม่แก้ มุมกางนิ้วจะดูแคบกว่าจริง และระยะจะเปลี่ยนเมื่อหมุนมือ หลังแก้ ทุกแกนมีหน่วยเท่ากัน (หน่วย = ความสูงภาพ)
ในหน้า math-test เราแปลงเป็นพิกเซลตรง ๆ (x·W, y·H, z·W) ซึ่งให้ผลแบบเดียวกัน

## 1. ระยะทาง 3 มิติ — `dist(A, B)`

$$d(A,B) = \sqrt{(x_A-x_B)^2 + (y_A-y_B)^2 + (z_A-z_B)^2}$$

ทฤษฎีบทพีทาโกรัสใน 3 มิติ เป็นฐานของทุกฟังก์ชันที่เหลือ **ปัญหา:** ค่านี้ขึ้นกับระยะมือจากกล้อง มือใกล้กล้อง 2 เท่า ค่าก็ใหญ่ขึ้น 2 เท่า

## 2. ขนาดฝ่ามือ (ไม้บรรทัดของมือ) — `palmScale(pts)`

$$S = d(P_0, P_9)$$

ระยะจากข้อมือ (จุด 0) ถึงข้อโคนนิ้วกลาง (จุด 9) คือความยาวกระดูกฝ่ามือ (metacarpal) ซึ่ง **ไม่งอ** ไม่ว่าจะกำมือหรือแบมือ

**ทำไมไม่ใช้จุด 0 กับ 12 (ปลายนิ้วกลาง):** ระยะ 0–12 ลดลงเกือบครึ่งเมื่อกำมือ ไม้บรรทัดที่ยืดหดได้เองใช้วัดอะไรไม่ได้ (การทดสอบใน `tests/geometry.test.mjs` แสดงว่า 0–12 เปลี่ยนเกิน 1.5 เท่า แต่ 0–9 ไม่เปลี่ยนเลย)

**กรณีพิเศษ:** ถ้า S = 0 (จุดซ้อนกัน/ข้อมูลเสีย) ฟังก์ชันจะโยน error ภาษาไทย "ขนาดฝ่ามือเป็นศูนย์…" แทนการคืนค่า NaN เงียบ ๆ และถ้าจุดไม่ครบ 21 จุดก็โยน error เช่นกัน

## 3. ระยะที่หารด้วยขนาดฝ่ามือ — `normDist(pts, i, j)` ⭐ สำคัญที่สุด

$$nd(i,j) = \frac{d(P_i, P_j)}{S}$$

เมื่อมือเข้าใกล้กล้อง k เท่า ทั้งตัวตั้งและตัวหารใหญ่ขึ้น k เท่าพร้อมกัน:

$$\frac{k \cdot d(P_i,P_j)}{k \cdot S} = \frac{d(P_i,P_j)}{S}$$

k ตัดกันหมด ค่าจึง **ไม่ขึ้นกับระยะกล้อง** และไม่ขึ้นกับขนาดมือของแต่ละคน (มือเด็กกับมือผู้ใหญ่ ใช้เกณฑ์เดียวกันได้)
เกณฑ์ผ่านของแลป: เลื่อนมือเข้า-ออก ค่าในคอลัมน์ขวาเปลี่ยนไม่เกิน 5% (max ÷ min ≤ 1.05)

## 4. มุมที่ข้อต่อ — `angle(A, B, C)`

$$\theta = \arccos\left(\frac{\vec{BA}\cdot\vec{BC}}{|\vec{BA}|\,|\vec{BC}|}\right) \times \frac{180}{\pi}$$

มุมที่จุด B ระหว่างเวกเตอร์ B→A กับ B→C (องศา) ใช้ผลคูณจุด (dot product) ค่าที่ได้อยู่ระหว่าง 0°–180°
นิ้วเหยียดตรง มุมที่ข้อ ≈ 180° ยิ่งงอมุมยิ่งเล็ก มุมไม่ขึ้นกับระยะกล้องโดยธรรมชาติ (ขยายรูปแล้วมุมเท่าเดิม)
ก่อนหารจะบีบค่าให้อยู่ใน [−1, 1] กันปัดเศษแล้ว arccos ได้ NaN

## 5. ความงอของนิ้ว — `fingerCurl(pts, finger)`

ใช้มุม 3 ข้อ: θ_MCP (ข้อโคน), θ_PIP (ข้อกลาง), θ_DIP (ข้อปลาย)

$$\bar\theta = \frac{0.5\,\theta_{MCP} + \theta_{PIP} + \theta_{DIP}}{2.5}, \qquad curl = \mathrm{clamp}\left(\frac{180 - \bar\theta}{110},\ 0,\ 1\right)$$

นิ้วโป้ง (งอได้แคบกว่า): $curl_{thumb} = \mathrm{clamp}\left(\frac{180 - (\theta_{MCP}+\theta_{IP})/2}{70}, 0, 1\right)$

0 = เหยียดตรง, 1 = งอสุด ข้อโคนให้น้ำหนักครึ่งเดียวเพราะ MediaPipe วัดมุมข้อโคนได้ไม่แม่นเท่าข้ออื่น
ใช้ในท่า **กำมือ** (เฉลี่ย 4 นิ้ว) และ **แตะนิ้วทีละนิ้ว** (นิ้วเดียวงอ ที่เหลือเหยียด)

## 6. มุมกางระหว่างสองนิ้ว — `spread(pts, f1, f2)`

$$spread = \angle\left(\vec{K_1T_1},\ \vec{K_2T_2}\right)$$

มุมระหว่างเวกเตอร์ "ข้อโคนนิ้ว → ปลายนิ้ว" ของสองนิ้ว (K = knuckle, T = tip) ใช้ในท่า **แบมือกางนิ้ว** (นิ้วชี้กับนิ้วก้อย เพราะห่างกันที่สุด)

## 7. ฝ่ามือหันเข้ากล้องไหม — `handFacingCamera(pts)`

$$\vec{n} = (P_5 - P_0) \times (P_{17} - P_0), \qquad r = \frac{|n_z|}{|\vec n|}$$

ผลคูณไขว้ (cross product) ของสองเวกเตอร์บนฝ่ามือ ได้เวกเตอร์ตั้งฉากกับฝ่ามือ ถ้าตั้งฉากชี้เข้ากล้อง (แกน z) → r ≈ 1 = หันเข้ากล้อง; ถ้าหันข้าง → r ≈ 0
เกณฑ์ r ≥ 0.6 = หันเข้ากล้อง ใช้เตือนผู้ใช้ เพราะเมื่อมือหันข้าง จุดของนิ้วจะบังกันและค่าทุกตัวเพี้ยน (ปรากฏการณ์ที่อธิบายในบทที่ 5)

## 8. แปลงค่าเป็นคะแนน 0–1 — `scoreLow`, `scoreHigh`

$$scoreLow(v) = \mathrm{clamp}\left(\frac{zero - v}{zero - full}\right) \qquad scoreHigh(v) = \mathrm{clamp}\left(\frac{v - zero}{full - zero}\right)$$

ใช้ใน `gestures.js` เช่น ท่าจีบ: ระยะ 4–8 ≤ full → คะแนน 1, ≥ zero → คะแนน 0 ระหว่างนั้นเป็นเส้นตรง
