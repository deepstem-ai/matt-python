# WORKFLOW.md — พิธีประจำแลปของทีม

## 🟢 ตอนเริ่มแลป (5 นาที)
1. `git status` — ต้องขึ้นว่า "nothing to commit" (ถ้าไม่ใช่ ให้ commit งานเก่าก่อน)
2. เปิด `docs/PROJECT-MAP.md` ดูว่าแลปนี้เป็นเจ้าของไฟล์ไหน ไฟล์ไหนห้ามแตะ
3. อ่านหัวคอมเมนต์ 3 บรรทัดในไฟล์ว่างที่จะเขียน
4. เติมช่องว่าง ___ ในคำสั่งของแลปร่วมกันเป็นทีม **ก่อน** ดูคำแนะนำของ AI
5. เปิดแอปผ่าน `start.bat` ให้แน่ใจว่าของเดิมยังทำงาน
6. ส่งคำสั่งให้ Claude Code (สูตร 5 บรรทัด) → อ่านแผน → พิมพ์ `GO`

## 🟡 กลางแลป เมื่อโค้ดเริ่มพัง
1. **หยุด** อย่าสั่ง AI "แก้อีก" ซ้ำ ๆ เกิน 2 รอบ
2. กด F12 → Console คัดลอกบรรทัดสีแดงบรรทัดแรก
3. `git diff` ดูว่าเปลี่ยนอะไรไปตั้งแต่จุดเซฟล่าสุด
4. แจ้ง AI แบบคำสั่งแข็ง: ทำอะไร เห็นอะไร คาดว่าจะเห็นอะไร + ข้อความ Console (`prompts/02-fix-bug-template.md`)
5. ยังไม่หาย → ย้อนไฟล์ที่พังด้วย `git checkout -- ไฟล์` แล้วเริ่มใหม่ด้วยคำสั่งที่เล็กลง
6. พังหนักทั้งโปรเจกต์ → `git checkout lab-XX` ดูของเดิมที่ใช้ได้ (กลับมาด้วย `git checkout main` หรือ `master`)
7. ระหว่างทาง ทุกครั้งที่อะไรเริ่มใช้ได้ → `git add .` + `git commit` จุดเซฟเล็ก ๆ

## 🔵 ตอนจบแลป (10 นาที) — ห้ามข้าม
1. ทดสอบตามข้อ "YOU PASS THIS LAB WHEN" ครบทุกข้อ
2. เก็บหลักฐานใน `evidence/lab-XX/` (ภาพหน้าจอ ตัวเลข FPS ฯลฯ)
3. `git add .` → `git commit -m "Lab XX: <อะไรใช้ได้แล้ว>"`
4. `git tag lab-XX`
5. อัปเดต ✅ ใน `docs/PROJECT-MAP.md` และจดบันทึกประจำวัน 2-3 บรรทัด (ช่วยเขียนรายงานได้ครึ่งหนึ่ง)
6. คำสั่ง AI ที่ได้ผลดี เก็บลง `prompts/`
