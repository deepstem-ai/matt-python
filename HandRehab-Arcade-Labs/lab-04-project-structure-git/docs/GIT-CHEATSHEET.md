# GIT-CHEATSHEET.md — 8 คำสั่ง git ที่ทีมเราใช้จริง

| คำสั่ง | ใช้เมื่อไร (1 ประโยค) |
|---|---|
| `git init` | ใช้ **ครั้งเดียว** ตอนเริ่มโปรเจกต์ เพื่อให้โฟลเดอร์นี้เริ่มจำประวัติได้ |
| `git add .` | ใช้ก่อน commit ทุกครั้ง เพื่อหยิบไฟล์ที่แก้ทั้งหมดใส่ "ตะกร้า" เตรียมบันทึก |
| `git commit -m "ข้อความ"` | ใช้เมื่อของทำงานได้แล้ว เพื่อบันทึกจุดเซฟ พร้อมข้อความว่า **ตอนนี้อะไรใช้ได้** |
| `git status` | ใช้เมื่อไม่แน่ใจ ว่าตอนนี้มีไฟล์ไหนถูกแก้ / ยังไม่ได้บันทึก |
| `git log --oneline` | ใช้เมื่ออยากดูรายการจุดเซฟทั้งหมดที่ผ่านมา (บรรทัดละจุด) |
| `git diff` | ใช้ก่อน commit (หรือหลัง AI แก้โค้ด) เพื่อดูว่า **เปลี่ยนอะไรไปบ้าง** ทีละบรรทัด |
| `git checkout -- ไฟล์` | ใช้เมื่อไฟล์พังหรือถูกลบ เพื่อดึงไฟล์นั้นกลับเป็นแบบ commit ล่าสุด (`git checkout lab-03` = ย้อนไปดูทั้งโปรเจกต์ตอนจบ Lab 03) |
| `git tag lab-04` | ใช้ตอนจบแลป เพื่อแปะป้ายชื่อถาวรให้จุดเซฟนั้น ย้อนกลับได้ง่าย |

## commit ต่างจาก tag อย่างไร — เปรียบกับเซฟเกม 🎮
- **commit = กดเซฟเกม** เซฟบ่อยแค่ไหนก็ได้ ทุกครั้งที่ผ่านด่านย่อย ได้ช่องเซฟใหม่เรียงต่อกันไปเรื่อย ๆ แต่ละช่องมีรหัสยาว ๆ จำยาก (เช่น `a1b2c3d`)
- **tag = ตั้งชื่อช่องเซฟสำคัญ** เช่น "ก่อนสู้บอส" หรือ "จบบทที่ 4" ป้ายชื่อนี้ติดกับช่องเซฟนั้นตลอดไป อยากกลับมาเล่นตรงนี้เมื่อไรก็เลือกจากชื่อได้ทันที ไม่ต้องจำรหัส
- สรุป: **commit บ่อย ๆ ระหว่างทาง, tag ครั้งเดียวตอนจบแลป** (`lab-01`, `lab-02`, ...)
