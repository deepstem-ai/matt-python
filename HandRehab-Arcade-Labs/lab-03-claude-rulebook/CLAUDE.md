# CLAUDE.md — กฎประจำโปรเจกต์ HandRehab Arcade

> AI ต้องอ่านไฟล์นี้ก่อนทำงานทุกครั้ง และทำตามทุกข้อโดยไม่ต้องให้เตือน

## ส่วนที่ 1 — บริบทของโปรเจกต์
1. ชื่อโปรเจกต์: **HandRehab Arcade** — เว็บแอปเกมฝึกมือและนิ้วด้วยกล้อง + AI
2. สร้างให้: **ผู้สูงอายุ และผู้ที่ต้องฟื้นฟูการใช้มือ** (เช่น หลังโรคหลอดเลือดสมอง, ข้อนิ้วติด, มือสั่น) รวมถึงนักกายภาพบำบัด / ผู้ดูแลที่ช่วยดูผล
   - ผู้ใช้อาจสายตาไม่ดี มือสั่น ไม่คุ้นคอมพิวเตอร์ → ทุกอย่างต้องใหญ่ ชัด และให้อภัยความผิดพลาด
3. สร้างโดย: ทีมนักเรียน **ทีม NeonHands จากโรงเรียนของเรา**
4. เปิดแอปผ่าน `start.bat` / `http://localhost` เท่านั้น ห้ามพึ่ง `file://`

## ส่วนที่ 2 — เทคโนโลยีที่อนุญาต
1. ใช้ได้เฉพาะ HTML, CSS, JavaScript ธรรมดา — **ห้าม npm, ห้าม build tool, ห้าม TypeScript, ห้ามเฟรมเวิร์ก** (React, Vue ฯลฯ)
2. ไลบรารีภายนอกที่อนุญาตมี **ตัวเดียว**: MediaPipe Tasks Vision โหลดจาก CDN (ล็อกเวอร์ชันไว้)
3. เก็บข้อมูลด้วย **IndexedDB** ของเบราว์เซอร์ ไม่มีเซิร์ฟเวอร์ ไม่มีคลาวด์ ข้อมูลผู้ใช้ไม่ออกจากเครื่อง
4. กราฟ ตัวกรอง AI เล็ก ๆ ฯลฯ ให้เขียนเองทั้งหมด

## ส่วนที่ 3 — กฎการเขียนโค้ด
1. ทุกไฟล์ต้องมี **คอมเมนต์ภาษาไทย** ที่มือใหม่อ่านรู้เรื่อง อธิบายว่า "ทำอะไร" และ "ทำไม"
2. ไฟล์เดียว **ห้ามยาวเกิน 200 บรรทัด** — ถ้าเกิน ให้แยกเป็นหลายไฟล์ (โมดูล)
3. **ห้ามเขียนรหัสสีตรง ๆ** (เช่น `#22D3EE`) ให้เรียกผ่านตัวแปรใน `css/tokens.css` เท่านั้น เช่น `var(--primary)`
   - ระหว่างนี้ (ก่อน Lab 04–05) ตัวแปรสีอยู่ใน `:root` ของ `index.html` — ให้ใช้ตัวแปรชุดนั้น
4. ปุ่มและสิ่งที่กดได้ทุกอัน **สูงอย่างน้อย 56px**
5. ข้อความบนจอเป็นภาษาไทย ห้ามปล่อย **จอว่าง** — ทุกข้อผิดพลาดต้องมีข้อความไทย + ปุ่มให้กด (เช่น ลองใหม่)
6. หน้าที่ใช้กล้องต้องปิดกล้องคืนเครื่องเมื่อออกจากหน้า
7. ตั้งชื่อตัวแปรให้สื่อความหมาย ห้ามใช้ชื่อกว้าง ๆ อย่าง `data`, `temp`, `x2` (กฎเฉพาะทีมเรา)

## ส่วนที่ 4 — AI ต้องทำตัวอย่างไร
1. **อ่านไฟล์ก่อนแก้ทุกครั้ง** ห้ามเดาเนื้อหาไฟล์
2. งานที่แตะ **มากกว่า 2 ไฟล์** → เสนอแผนก่อน (ไฟล์ไหน แก้อะไร ทำไม) แล้ว **รอจนฉันพิมพ์ `GO`** จึงเริ่มเขียน
3. **ห้ามลบหรือเขียนทับโค้ดที่ทำงานได้แล้ว** โดยไม่ถามก่อน — ถ้าจำเป็นต้องแก้ ให้บอกว่าจะแก้ตรงไหนและเพราะอะไร
4. **ห้ามติดตั้งอะไรเอง** — ถ้าคิดว่าจำเป็น ให้บอกชื่อและเหตุผล แล้วรอฉันอนุมัติ
5. แก้เฉพาะสิ่งที่สั่ง ห้าม "จัดระเบียบให้ด้วย" ในไฟล์หรือฟังก์ชันอื่นที่ไม่เกี่ยว
6. เสร็จงานแล้ว สรุปสั้น ๆ: แก้ไฟล์อะไรบ้าง + ฉันต้องกดอะไรแล้วจะเห็นอะไรบนจอ
7. ถ้าคำสั่งไม่ชัด ให้ถามกลับ 1–3 ข้อ ก่อนลงมือ อย่าเดา

## ส่วนที่ 5 — ปุ่ม/ส่วนควบคุมที่แต่ละหน้าต้องมี (บันทึกไว้ล่วงหน้า)
1. หน้ากล้อง: ปุ่มเปิดกล้องใหญ่, ป้าย FPS มุมขวาบน, กล่องแจ้งปัญหา + ปุ่มลองใหม่
2. หน้าลงทะเบียน: ช่องกรอกข้อความ, ดรอปดาวน์, สไลเดอร์ (ระดับมือสั่น), ปุ่มถัดไป/ย้อนกลับ
3. หน้าเกม: แคนวาสวาดภาพ, แถบเวลา, ตัวเลขคะแนน, ปุ่มหยุดชั่วคราวขนาดใหญ่
4. หน้าผลลัพธ์: กราฟ, ปุ่มบันทึก CSV / รูปภาพ, ปุ่มกลับหน้าหลัก
